# 评估课程链接

两个问题分开回答，结论可以不同：
- **收录**：对网站读者（想系统学 AI Agent 开发的人）是否够格。标准是 `UPDATE_PLAYBOOK.md` 的评分表。
- **学习**：对用户本人值不值得花时间。看它和本站学习路线（`content/phases.json` 的 P0–P8）的衔接、和已收录资料的重叠。

用中文，简洁。不要改任何文件，直到用户明确说"收录"。

## 步骤

1. **查重先行**（项目根目录运行）：
   `python3 scripts/lookup.py URL [URL ...]`
   输出已收录 / 已审核 / 相近条目 / GitHub star 与最近提交。
   - 已收录：说明对应条目，只回答"值不值得学"，不再打分。
   - 已审核且理由是"首轮审核：…"：这是批量初筛，可以重新判断；单独审核过的除非内容有大更新否则沿用。
   - 中文翻译版（宝玉等）对应的英文原文已收录：不单独收，可提议加进原条目的 `extra_links`。

2. **读原文**，不凭标题、star 和简介下结论：
   - 网页：WebFetch 或 `mcp__exa__web_fetch_exa`；需要渲染或登录的用浏览器工具。
   - 仓库：`gh api repos/OWNER/REPO/readme --jq .content | base64 -d`，再看目录树（`gh api repos/OWNER/REPO/git/trees/HEAD?recursive=1`）和 1–2 章正文、代码能否对上当前 API。
   - 课程平台/视频：读大纲、每节标题和时长；能拿到字幕或讲义就抽读一节。
   - PDF：用 PDF 读取工具读目录和关键章节。
   - 读不到的部分明说"没读到"，并据此降低结论把握。

3. **打分**：按 `UPDATE_PLAYBOOK.md` 的"质量评分标准"和"一票否决"。每一维给一句依据。"新颖"一维必须点名对比 lookup 列出的相近条目：比它们新在哪、好在哪，还是重复。

4. **范围判断**（本站主题是"开发 Agent"）：
   - 讲 agent / harness / 上下文工程 / 工具设计 / 评估 / 多智能体原理或实现的：在范围内。
   - **AI 编程工具的使用教程**（Claude Code、Codex、Cursor、Copilot 怎么用）：只有当它讲清可迁移的设计思想（上下文管理、子代理、Skills/hooks、规范驱动、AGENTS.md 这类）时才收，放 `articles` 或 `official-sdk`；纯快捷键、配置、换模型、拼车/代理教程不收。但这类资料对用户本人可能仍值得学，在"学习"结论里单独说。
   - 工具/框架本身：按一票否决处理，除非它就是学习材料或业界标杆。

5. **定位**：阶段 Px、`category`（见 `data/resources.json` 的 `categories`）、`type`、`format`。`pick` 全站 ≤ 6，几乎不用。

6. **学习建议**：
   - 值得学 / 选学 / 跳过，一句理由。
   - 前置知识、预计耗时（按章节数或视频时长估，注明是估计）。
   - 最值得学的章节，具体到章节名、集数或文件路径；可跳过的部分。
   - 学完能产出什么，接上哪个阶段的产出（见 `content/phases.json`）。
   - 如果已收录资料里有更好的替代，直接说先学那个。

## 输出

单个链接：

```
结论：收录 / 不收录｜值得学 / 选学 / 跳过
评分：X/10（深度 a · 实践 b · 可信 c · 新颖 d · 维护 e）
是什么：一句话（基于读到的内容）
对比已有：与 <已收录条目 id/标题> 的差异
放哪：阶段 Px，category=…，type=…，format=…
最值得学：1. … 2. … 3. …
可跳过：…
耗时/前置：…
风险/注意：付费、过时、AI 批量生成、需翻墙/账号等
```

多个链接：先一张表（标题｜收录?｜分数｜学习建议｜阶段），再对"收录"或"值得学"的逐个给"最值得学"，其余一句话带过。

最后问一句是否收录（列出建议收录的条目）。

## 收录动作（用户确认后）

1. 往 `data/resources.json` 的 `resources` 追加条目，字段按 `UPDATE_PLAYBOOK.md` 的"数据格式"：`id` 唯一小写短横线；`added` 用今天日期；`score` 填评分；`desc` ≤ 60 字且基于原文；有仓库就填 `github`；`stars`/`pushed_at`/`last_checked` 填 `null`、`status` 填 `"ok"`，由 `check.py` 刷新。
2. 本次评估的每个链接（收录和拒绝都算）写进 `data/reviewed.json`，键用 `norm_url`，值 `{"date","decision","score","reason"}`。
3. 如果明显好过某阶段现有读物，提议改 `content/phases/pX.html`（每阶段保持 4–7 条，加一条就考虑淘汰一条），用户同意再改。
4. `data/changelog.json`：今天已有条目就把新 id 加进它的 `added`，并更新 `summary`/`stats`；没有就在最前面新建。
5. `python3 scripts/build.py` 必须通过；失败就修。
6. 不 commit、不 push，除非用户要求。

## 原则

- 不编造章节名、star、作者背景；都来自实际打开的页面。
- 营销软文、核心内容在付费墙后、与已收录高度重复：直接拒绝，给出理由。
- 中英文同一标准。star 多不等于好，官方文章没有 star 也不扣分。
- 用户的学习时间比资料库条数重要：推荐学习时宁少勿多，给出先后顺序。
